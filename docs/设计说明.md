## 1. 定位：扩展，而不是重复

原版化学是**「液体容器里的组分」**体系：组分只有抽象的
「酸 / 碱 / 水 / 酒精 / 脂合剂 / 还原剂 / 稳定剂 / N-羟甲基碱 / 氯」等，
以 μl 计量、按温度驱动 22 项反应；设备是搅拌机、加热板、蒸发器、
化学制剂成型机、成分光谱仪、熔炉、净水器等。

**本 Mod 新增的是原版没有的「具名化合物」与「缺失的单元操作」，不重复造轮子：**

- 具名基础药剂：HCl、H2SO4、HNO3、NaOH、H2O2、NaCl、CaCO3、KNO3、
  KMnO4、CuSO4、NH4NO3、Ca(ClO)2、Cl2、H2、O2、N2、NH3、HCl(g)、CO2、
  乙醇、蒸馏水、乙烯、笑气、咖啡豆糊、咖啡因等。
  它们以**独立瓶装 / 罐装物品**存在，可直接拾荒、购买、交易、投料。
- 设备全部避开原版已有清单：电解槽、气体发生器、合成反应釜、冷凝吸收塔、
  结晶器、高压合成塔、分馏柱、滴定台、静置滗析槽、气体洗涤塔、气体灌装台、
  过滤台、大型加热台（共 13 台）。
- 补足原版没有的**器材与耗材**：烧杯、鹅颈瓶、锥形瓶、试管架、
  化学滤纸 / 精密滤纸 / 无灰定量滤纸、棉灯芯 / 陶瓷灯芯、酒精灯、酒精喷灯。

## 7. 污染物不可完全提纯（用户第 10 轮重点）

**8 类污染物 tag**（`fc_contam_*`）与等效粒径（μm，与原版组分粒径表一致）：

| 污染物 | 粒径 | 污染物 | 粒径 |
|---|---|---|---|
| 化学污染物 chem | 2 | 有机废物 organic | 40 |
| 重金属 heavy | 12 | 微生物 micro | 50 |
| 微塑料 plastic | 25 | 物理污染物 phys | 100 |
| 矿物质 mineral | 30 | 不溶性碎屑 debris | 200 |

- **滗析只能移除可沉降的 `phys` / `debris`（各移走 85%）**；
  游离的 `chem`(2) / `heavy`(12) / 微生物 / 微塑料**完全保留**——这是用户明确纠正过的点。
- **过滤按孔径拦截，且每类保留 0.7% 残留下限**（`ChemLab.ResidualFloor = 70`，即 0.70%）：

| 滤纸 | 等效孔径 | 耐久 | 能拦住 | 拦不住 |
|---|---|---|---|---|
| 化学滤纸 filter_paper | 22 μm | 8 | 物理污染物、不溶性碎屑、矿物质、有机废物 | 化学污染物(2)、重金属(12)、微塑料(25) |
| 精密滤纸 filter_paper_fine | 5 μm | 5 | 上述 + 重金属、微塑料 | 化学污染物(2) |
| 无灰定量滤纸 filter_paper_ash | 2 μm | 3 | 上述 + 化学污染物 | 仍受 0.7% 下限 |

- 因此 `ChemLab.PurityFrom()` 反推的纯度**永远 < 100%**（硬上限 = 100% − 0.7% × 8 类），
  过滤链达不到「实验室纯级」满值，也不会把污染物清零。这是「滗析/过滤只能提高纯度、
  无法完全提纯」的数值实现。

## 8. 实时大型加热台（用户第 10 轮）

- 设备 `heating_platform` **不走夜间结算**（`ChemRecipes.IsRealtime`），
  由 `ModHelper.StartCoroutine` 每秒 tick（禁止线程，`<Capabilities />` 为空）。
- **必须放反应容器**（烧杯 / 鹅颈瓶 / 锥形瓶 / 试管架）与**加热器**（酒精灯 / 酒精喷灯）；
  加热器**必须插灯芯**（棉灯芯耐久 20 / 陶瓷灯芯耐久 40）并加**酒精燃料**。
- **燃料纯度决定加热效率**：`HeatFactor(p) = 0.4 + 1.2×p/100`（0.4 ~ 1.6），
  `FuelBurnRate(p) = 1.6 − 0.9×p/100`（纯度越低烧得越快）。
  原版小瓶酒精 = 175 ml 酒精 + 75 ml 水 → **70% 纯度**。
- **升温/冷却套原版加热板公式**：
  - 升温：`min(目标, T + (目标−T)×因子/350 + 1)`（低档目标 99 °C、高档 160 °C）
  - 冷却：`26 + (T−26)×exp(−6.25/(√V+11))`，V 为总液量 μl，室温 26 °C
  - 模组数 2–4 时 26–160 °C 可调，模组数 3/4 另有 ×4 / ×16 加速分支
- **温度落入热反应温区后按秒累积**，达到所需秒数即产出；**超温则降解为废渣**。
- 6 条实时热反应（P3b 起删除「咖啡因热萃取」，原 7 条）：

| 热反应 | 方程式 | 温区 °C | 秒 |
|---|---|---|---|
| 盐酸蒸馏提纯 | HCl(aq) → 更纯 HCl(aq) | 78–110 | 20 |
| 乙醇脱水制乙烯 | C2H5OH --浓 H2SO4--> C2H4↑ + H2O | 160–180 | 30 |
| 高锰酸钾热分解 | 2KMnO4 → K2MnO4 + MnO2 + O2↑ | 200–260 | 25 |
| 硝酸铵热分解 | NH4NO3 → N2O↑ + 2H2O | 180–250 | 25 |
| 双氧水热分解 | 2H2O2 → 2H2O + O2↑ | 80–120 | 15 |
| 硝石制硝酸（加热） | KNO3 + H2SO4 → KHSO4 + HNO3↑ | 120–160 | 30 |

## 10. 多级合成链（T1 → T4）

**T1 一级**（原料 → 气体 / 酸碱）
- 氯碱法：2NaCl + 2H2O --电解--> Cl2↑ + H2↑ + 2NaOH
- 大理石制 CO2：CaCO3 + 2HCl → CaCl2 + H2O + CO2↑
- 双氧水催化分解：2H2O2 --MnO2--> 2H2O + O2↑
- 高锰酸钾热分解、铵盐加碱：见 §8 / 夜间配方

**T2 二级**（气体 / 酸碱 → 中间体）
- 氢氯合成：H2 + Cl2 --点燃--> 2HCl
- 哈伯法：N2 + 3H2 ⇌ 2NH3（Fe，450 °C，20 MPa）
- 氯化氢吸收：HCl(g) + H2O → HCl(aq)
- 硝石制硝酸、奥斯特瓦尔德法、湿法制硫酸、酸碱中和滴定

## 11. 毒性 / 致命性 / 成瘾性（复用原版公式）

原版：`L=Σ(组分 μl × 毒性系数)`，L≥1000 致命、750≤L<1000 有毒；
`E=Σ(组分 μl × 欣快系数)`，欣快等级 0–4；另有赛纳普斯戒瘾、避孕激素识别。

本 Mod 每件物品带 `fc_tox` / `fc_euph` / `fc_controlled` tag，
`ChemRuntime` 按同样公式计算 `Lethality()` 与 `EuphoriaTier()`，
并在 `OnCreateTooltipLate` 追加一行「纯度 X% · 毒性 · 欣快等级 N」。
虚构违禁品标记为管制（`contraband` tag + 高欣快/毒性），
设计上会接入原版的售后投诉、回购与安保追踪路径（**需实机验证**）。

### 排气嫌疑度（模组计数 + **已接入原版治安部 ENDANGERMENT**）

> 第 13 轮 Lead 决策变更：不再只做模组自有计数，而是**按 `docs/api-findings.md` §2.4 的 guard 方案接入原版治安部**（默认开启、可在模组设置关闭）。

- **风险事实（保留）**：官方 modding API **没有**暴露写治安部 heat / 调查进度的接口；
  本实现用的是**未文档化**的 public 成员 `PlayerStore.Instance.secData.CommitCrime(SecData.ENDANGERMENT, amount)`，
  它随游戏版本可能改名/改语义，因此才做成可关闭。
- **双层机制**：
  1. 模组自有计数：`ModHelper.SetModDataInt("exhaust_raw")` 按局存档，用于提示框展示与
     `ChemLab.SuspicionFrom(raw, ventLevel)`（`raw × 100 × 倍率bp / 10000`）。
  2. 原版写入：`ChemRuntime.AddExhaust(units)` 内调 `CommitVanillaEndangerment(units)`：
     先 `PlayerStore.HasInstance` 判空（**绝不**在菜单/无存档时触发 `Instance` 惰性新建 store），
     再 `CommitCrime(SecData.ENDANGERMENT, units × 10 × 排风倍率bp / 10000)`；异常 catch + log，不影响玩法。
- **折算量**：`VanillaEndangermentPerUnit = 10`（静态设计值，**未实机验证平衡**）。
- **开关**：模组设置 `vanilla_security`（`Gameplay` 分类，**默认开启**）。关闭后只保留模组自有计数，
  不写原版 `ENDANGERMENT`；设置项本地化键 `cfg_vanilla_security` / `cfg_vanilla_security_tip`。
- 计入气体：只有毒性/刺激性气体（Cl2、HCl(g)、NH3）计入，CO2/O2/N2/H2/乙烯/笑气不计；
  单次排放单位按毒性系数分级：≥3.0 记 2，否则记 1（氯气 2，氯化氢/氨气 1）。
- 排风倍率（无服务 10000 / 基础 5500 / 进阶 1200 → ×1.00 / ×0.55 / ×0.12）**同时**削减
  模组计数增速与原版 `ENDANGERMENT` 写入量：同一 raw，进阶严格小于基础、基础严格小于无服务。
- 提示框追加一行 `suspicion_profile`（{0}=嫌疑度，{1}=排风档位），文案明确写「已按排风倍率折算
  写入原版治安部 ENDANGERMENT，可在模组设置关闭」。
- **未验证项（如实）**：写入量平衡（10/单位是否产生可感知的调查推进）、调查节奏
  （是否会造成无故调查/判罚）、起始专精 `IsIntimidating`/`IsBlabbermouth` 改数值并消耗 RNG 的影响、
  关闭开关后是否真的零写入 —— 全部**未做游戏内验证**。

### 13.3 打开调试生成窗口：**首选快捷键（默认 F10，可重绑）**

> **为什么不是 F9**：F9 调试面板 / F8 控制台是游戏的开发工具，受 `DevTools.IsEnabled` 门控（需要游戏 exe 同级空 `dev.txt` 且重启游戏），
> 正式安装下不出现 —— 用户实测「F9 里没有 FreeChem 按钮」就是这个原因。因此第 15 轮改为**模组自注册的快捷键**，不依赖 `dev.txt`。

**首选入口（正式可用）**
1. 先在**模组设置**里打开「调试模式」（默认关；窗口能打开，但**不开启就不会实际生成**，状态行会提示去开启）。
2. 进店铺存档后按 **F10**（默认值）→ 打开/关闭生成窗口（同一个窗口，再按一次关闭）。
   快捷键在 **游戏「选项 → 按键绑定」** 里可改，条目名「**FreeChem 调试生成窗口**」（键 `option_debug_open` / `option_debug_open_tip`）；
   值持久化在 `PlayerPrefs`（`free_chem.debug_hotkey`），非法/无值回退 F10。
   注册：`ModHelper.AddGameOptionKeyBind(ModId, OPTION_SECTION_KEYBIND, …)`；轮询用 `StartCoroutine`（**禁止线程**）+ `Input.GetKeyDown`
   + `KeyBindHelper.SuppressHotkeys`（重绑按键时静默）+ 每帧 guard（不在店铺场景则忽略）。
3. 在窗口里输入：**`1`–`85`**、**`spawn N`**（也接受 `id N` / `生成 N` / 全角数字），点「生成物品」。
4. 物品 **进后柜台**：目标 `EmporiumEntry.Instance.backInvinvElement`，实际放置用 **`GraphUtils.TryAcceptAllOrDestroy(back, item, "free_chem.debug_spawn")`**（bool 版：内部先 `TryAcceptAll`，没放下会自动 `DestroyIfUnplaced` + 日志，不会重复销毁）。

5. **后柜台放不下**时（两段失败处理，都会弹同一个提示）：
   - ① 先 `GraphUtils.CanAccept` 只读探测（不改状态）；失败 → `item.Destroy()` → 弹提示；
   - ② 探测通过但 `TryAcceptAllOrDestroy` 返回 false（内部已自动销毁物品）→ 同样弹提示。
   提示**优先用真正的原版 modal** `GenericConfirmationUIManager.Instance.OpenPanelSingleButton(正文, "确定", null)`

   单例为 null（如主菜单场景）或调用异常时**回退**到自建 meta 风格窗口（标题键 `debug_alert_title`）。
6. 另有「列出 ID 对照」按钮：把 1–86 逐条写进 F8 控制台日志（F8 同样受 dev.txt 门控；控制台不可用时仅无效，不影响生成）。

### 15.2 液体可倒入原版容器（500 ml/件守恒；P3a 起，原 250 ml）

- **映射表（10 条，近似；`ChemRecipes.PourParts` 纯数据表，每条百分比和 = 100）**：

| 模组液体 | 原版组分映射 | 说明 |
|---|---|---|
| 盐酸 HCl(aq) | `acid` + `water` | 强酸溶液 |

| 硝酸 HNO3 | `acid` + `water` | 强氧化性酸 |

## 17. 第 20 轮 P1c：多级提纯与 100% 分析纯

### 17.1 多级提纯（过滤台）

- 过滤台**每完成一次过滤**，产物的 `fc_purify_level` **+1（上限 5）**，并用**新等级**重算纯度。
- 残留下限随等级下降：`PurifyFloor(level) = 70 >> level`（内部单位 1/100 百分点）→

| 提纯等级 | 残留下限（每类） | 理论纯度上限（8 类污染物） |
|---|---|---|
| 0（未提纯） | 0.70% | **94.40%** |
| 1 | 0.35% | 97.20% |
| 2 | 0.17% | 98.64% |
| 3 | 0.08% | 99.36% |
| 4 | 0.04% | 99.68% |
| 5 | 0.02% | **99.84%** |

- **滗析不改变提纯等级**（保留原等级）；只有**过滤台**每过滤一次 +1。
- 滤纸仍按**孔径 + 耐久**消耗：要把等级推到 5、纯度推到 ≥99.5%，需要**多张无灰定量滤纸**反复过滤（成本高）。
- 纯度上限**任何等级都 < 100%**（level 5 也只有 99.84%）；tooltip 显示 `purify_level`「提纯等级 {0}」（**等级 0 不显示**，避免噪音）。

### 17.2 打印机第 15 模式：校准（100% 分析纯）

- 打印机激活循环现在是 **15 个模式**：14 个标签模式（P1b1）+ 第 15 个 **「校准（分析纯）」**（`printer_mode_calibrate`）。
- **校准步骤**（唯一 100% 纯度路径）：
  1. 切到「校准（分析纯）」模式；
  2. **用打印机点「催化剂套件」** → 充能 +1（上限 3；显示 `printer_charge`「催化剂充能：{0}」/ `printer_charge_ok`「已装填催化剂：{0}/3」；**消耗该催化剂套件**）；
  3. **点纯度 ≥ 99.5% 的本模组药剂** → 若充能 > 0：**100% 分析纯**（`printer_calibrate_ok`「校准成功：100% 分析纯」）：
     污染物清零、`fc_purify_level`=5、`fc_purity`=100、`fc_grade`=LabPure，并同步原版纯度 100 + `CreateLabPure()`（真实=标签=实验室纯级，价格 **+135%**），消耗 1 点充能。
- **失败分支**：纯度不足 → `printer_calibrate_fail_purity`「校准失败：纯度需 ≥99.5%（当前 {0}%）」；
  没有充能 → `printer_calibrate_fail_charge`「校准失败：请先装填催化剂（用打印机点催化剂套件）」。
- 非校准模式点催化剂套件**不消耗**；校准后**不再调用 `GradeProduct`**（保持 P1b1 语义）。
- `chem_lab_pure_100`「100% 分析纯」用于最终显示；这是**唯一**能把纯度做到 100% 的路径，且需要「多张无灰滤纸 + 催化剂」，成本显著。

### 17.3 未实机验证项（如实）
