# 交接：Probably Stolen（深空当铺）化学扩展模组 v3

## 目标

给 Probably Stolen 加一套化学配方：

1. **查表式配方，每条带反应时间**：投料并满足条件后，机器开始计时，界面显示进度条，时间到了出产物。游戏内**不做**逐帧的化学模拟。
2. **原版杂质 + 提纯玩法**：杂质**只用原版已有的**：物理杂质、化学杂质、重金属等，模组不新造杂质。新原料按原版的方式带上这些杂质，玩家用原版试剂和本模组新增的方法去除或提取，提取出来的东西还能再利用。
3. **简单的职业联动**：纯水、水培营养片、养殖用的两种激素、养鱼用品。

要求"尽可能贴近现实"：产物、纯度、副产物和反应时间都由离线生成器按真实化学规律算出来，再写进表里。

## 已知背景（来自 wiki，需在代码中确认）

- 原版化学：容器里的液体按温度发生反应；机器有混合、加热、蒸发、封装（Chem Finisher）；成品可做成药片、药瓶、注射器。
- 原版规模约为 36 种液体、7 个配方。纯度分档，最高档是 Lab Pure（+135%）。
- 我们玩的时候装了联机 mod，本模组必须和联机 mod 兼容。
- **原版杂质**（据 wiki）：Chemical Contaminant、Physical Contaminant、Microbes、Organic Waste。wiki 上没有列重金属，但用户说原版有，需要在代码里确认它的 ID。杂质本身就是容器里的液体组分；纯度 = 有效成分占总体积的比例。
- **原版去除机制**（据 wiki）：
  - 氯：把化学杂质降到 0.7%，并杀死微生物。
  - 酸和碱：互相中和，把有机废物转成矿物质，并杀死微生物。
  - 40% 酒精：杀死微生物。
  - 加热：70°C 开始杀死微生物，100°C 全部杀死；80°C 时有机废物分解，其中 1/3 变成物理杂质。
  - 稳定剂：和酸或碱一起沉淀成残渣。
  - Lipobond Agent：让脂肪沉淀。
  - 蒸发器：蒸掉水、酒精和 Lipobond Agent。

## 总体架构

```
[离线] Python 生成器
   物质表 + 反应参数（A、Ea、dH）+ 杂质规则
   → 按温度档算出：产物、纯度、副产物、反应时间
   → recipes.json
                │
[游戏] C# mod：读取 recipes.json 查表 → 计时 → 进度条 → 出产物
```

- 游戏内只做查表和计时，结果是确定性的，联机天然同步。
- 改参数后重跑生成器即可，游戏代码不用动。

## 配方数据格式（草案，可根据侦察结果调整）

```jsonc
{
  "id": "neutralize_acid_impurity",
  "machine": "heater",
  "inputs":   [{ "item": "crude_water", "amount": 4 }, { "item": "sodium_carbonate", "amount": 1 }],
  "catalyst": null,
  "bands": [                                   // 按温度分档
    { "tMin": 15, "tMax": 40, "time": 120,     // 反应时间（游戏秒）
      "outputs": [{ "item": "treated_water", "amount": 4, "purity": 0.92 }] },
    { "tMin": 40, "tMax": 80, "time": 60,
      "outputs": [{ "item": "treated_water", "amount": 4, "purity": 0.95 }] }
  ]
}
```

- 统一用**字符串 ID**，不用数字编号。
- **反应时间由生成器算**：根据 Arrhenius 速率算出达到目标转化率所需的时间，再乘一个全局的游戏性缩放系数。温度越高越快，这一点是真实的；过高时可能纯度下降或出副产物。
- 档与档之间对纯度和时间做线性插值。
- **加载时校验**：引用了不存在的物品、ID 重复、温度档有重叠或缺口，都要报出明确的错误。
- 反应过程中条件跑出范围（比如温度变了）怎么处理：**暂停计时**，或者按新的温度档重新计算剩余时间。实现时选一种，写进文档。
- 杂质**不新建**，一律用原版的杂质液体。反应的副产物要么落到原版杂质里（比如过热分解时生成 Organic Waste 或 Physical Contaminant），要么落到本模组的残渣物品里。

## 杂质与提纯（用原版杂质）

- **杂质种类**：只用原版的物理杂质、化学杂质、重金属杂质，以及微生物、有机废物。ID 以侦察结果为准，模组不新造杂质类型。
- **生成**：新原料带杂质的方式**跟原版一致**（原版是随机的就随机，是固定比例就固定比例）。随机只在主机上生成。
- **影响**：沿用原版，杂质占体积 → 纯度下降 → 售价下降。另外，联动产品里重金属超标时会产生负面效果，比如植物、牲畜、鱼生长变慢或死亡，产品上要显示检测结果。
- **去除**：**优先复用原版规则**（氯、酸碱、酒精、加热、稳定剂沉淀、蒸发）。本模组只补原版没覆盖到的部分，每条都写成带反应时间的配方：

| 原版杂质 | 原版已有的手段 | 本模组补充（真实化学） |
|---|---|---|
| 化学杂质 | 氯（降到 0.7%）、酸碱中和 | 活性炭吸附，可以降到更低，满足纯水标准 |
| 物理杂质 | 沉淀（稳定剂） | 过滤、静置分层 |
| 重金属 | 侦察确认 | 调 pH 做氢氧化物沉淀，或加硫化物沉淀 → 过滤 → **重金属滤渣** |
| 微生物 | 氯、酸碱、40% 酒精、70–100°C | 原版够用，不加 |
| 有机废物 | 酸碱转成矿物质、80°C 分解 | 原版够用，不加 |

- **回收**：重金属滤渣是本模组**唯一新增的杂质类物品**，可以卖掉，或者处理后回收成试剂原料。这样"提炼出来"本身就是一条收益线。

## 联动内容（保持简单）

| 对象 | 产物 | 化学路线 |
|---|---|---|
| 水 | 纯水（蒸馏水 / 去离子水） | 蒸馏，或者沉淀加离子交换 |
| 水培 | 营养片（或营养液）、pH 调节剂 | 由磷酸盐、钾盐、硝酸盐配制，压片 |
| 养殖 | 原版的两种激素 | **抽象配方**，见下方"内容边界" |
| 养鱼 | 水质处理剂、除氯剂 | 中和、沉淀，硫代硫酸钠除氯 |

具体对接哪些原版物品 ID，以阶段 0 为准。

## 内容边界（必须遵守）

- 真实化学数据**只用于日常、无害的物质**：酸、碱、盐、溶剂、肥料、水处理、重金属沉淀等。
- **激素和游戏里的药物类产品一律用虚构化合物或抽象配方**，参数编得合理即可。**不得**写入现实中激素（尤其是合成代谢类固醇）或管制物质的真实合成路线、试剂、条件，代码、数据、注释里都不行。
- 重金属只用作**杂质**和**回收对象**。

## 离线生成器（Python）

- 物质表：字符串 ID、化学式或电荷、分子量、沸点、相态、基础售价。无机物尽量用离子表示，减少要注册的物质数量。
- 反应参数：A、Ea、dH、催化剂。按温度档算出转化率、纯度、副产物和**反应时间**。
- **自动配平检查**：原子数和电荷守恒，不守恒直接报错。
- **经济检查**：把所有配方连成图，按价格计算每个循环的收益，报出能刷钱的环。同时检查"单位时间收益"，避免某条配方明显碾压其他配方。
- 不要引入 RDKit 或 Open Babel。

## 规模目标

- C# 约 1,000–2,000 行，DLL < 100 KB，数据 < 200 KB；不算美术，整个 mod 约 1 MB。
- Python 生成器约 1,000–1,500 行。

## 推进顺序

1. 阶段 0 侦察，交出 `RECON.md`，**停下来等确认**。
2. **查表 + 计时 MVP**：只做 3 条配方，跑通完整链路（投料、计时、进度条、出产物），包括中途存档再读档。
3. **联机验证**：双人联机测试计时同步。
4. **杂质与提纯**：随机杂质、去除配方、回收物品。
5. **离线生成器**：用算出来的数值替换手写的数值，并跑经济检查。
6. **联动内容**：纯水、营养片、激素、养鱼用品，再加上重金属的负面效果。
7. 每个阶段结束时都写清楚测试步骤：单机、联机、卸载 mod 后的存档情况。
